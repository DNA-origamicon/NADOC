# Feature history audit and implementation plan

Audit date: October 14, 2026. Scope: native design and assembly history, mutation boundaries, generated/headless construction, desktop and VR history controls, persistence, and evaluation performance.

**Scope update:** the user has deferred assembly implementation until it is needed. The authoritative delivery sequence is now the [standard-part implementation plan](implementation.md), with [assembly work tracked separately](assembly_deferred.md). Assembly findings below remain audit evidence, not prerequisites for standard-part delivery. The inventory and coverage matrix retain the preimplementation source snapshot; source line numbers describe that snapshot.

NADOC has substantial recovery and editing infrastructure, but does not yet have a general proof that its editable commands reproduce the current design. Build that proof alongside the existing fast snapshot evaluator. First isolate mutation transactions and unify feature capabilities; then add incremental validation and command replay in feature families. Enforce strict agent commits only for families that meet the complete contract. Preserve interactive previews, legacy loading, recovery payloads, and invalid drafts throughout.

This is an implementation map, not a certification of existing designs. Source inspection establishes the gaps below; only the explicitly recorded tests were run. No application code, saved designs, user files, geometry rules, or runtime policies were changed by this audit.

- [Operation coverage](coverage.md) enumerates all 102 declared snapshot kinds and 39 minor subtypes, their literal recording call sites, dispatch support, and implementation phase. Missing literal sites are investigation targets, not proof of dead code.
- [Inventory](inventory.json) records all 837 route-decorated Python functions found under `backend`, 379 candidate recording/state call sites, 40 direct assignments to attributes named `design`, `assembly`, or `feature_log`, and every top-level Design/Assembly field. Counts include unmounted routes and nonmutation name matches; they are not counts of vulnerabilities or verified logging gaps.

- The inventory follows direct syntax, not a complete call graph. Aliases, dynamic callbacks, `model_copy` updates, nested object mutation, file writers, and external scripts require the runtime boundary audit in phase 1. An absence from the inventory is not evidence of safety.

## Findings requiring implementation

### F1 Restoration is not command regeneration

`SnapshotLogEntry` stores before and after state; `MinorMutationLogEntry` stores recorded changes. `_seek_feature_log` and `feature_evaluation.evaluate_child_prefix` can restore these without running the authored operation. `_delete_snapshot_feature_by_subtraction` removes IDs from saved states. These are useful recovery paths, not regeneration proofs.

**Required:** separate `restore`, `regenerate`, and `verify` capabilities. A strict verifier starts with an explicit empty/imported source and evaluates commands without reading their saved output as an input. It compares complete authoritative state and reports the earliest divergence. A cached result is reusable only after its recipe, inputs, dependencies, evaluator version, and policy are verified.

Sources: `backend/core/models.py:2019`, `backend/core/design_diff.py:1`, `backend/api/crud.py:7981`, `backend/core/feature_evaluation.py:208`.

### F2 Capability declarations already disagree

The shared snapshot dispatcher contains six branches. The minor dispatcher contains 14. These counts exclude specialized sweep/pattern/generated editing and are not overall coverage percentages. Assembly advertises 16 replayable kinds but implements 12 branches. Advertised-only kinds are `assembly-overhang-bind`, `assembly-overhang-bind-patch`, `assembly-overhang-unbind`, and `assembly-overhang-connection-delete`; the dispatcher falls through to HTTP 422 for them.

Frontend `REPLAYABLE_SUBTYPES`, `_EDIT_REPLAY_KINDS`, popover schemas, backend sets, and dispatch code maintain overlapping capability knowledge. Existing editors also have restrictions: most extrusion edits reject later snapshots; assembly edits support only the latest entry of four kinds. Linker/nanoparticle UI paths edit current objects rather than uniformly editing historical recipes.

**Required:** one versioned registry with independent restore/regenerate/edit/delete/repair capability fields, emitted to desktop/VR/agents. A registered command is not automatically fully editable. Establish parameter coverage and downstream behavior explicitly. First characterize the four assembly mismatches, then correct advertised capabilities or implement them; do not silently promise replay.

Sources: `backend/api/crud.py:8270`, `:8371`, `:8795`; `backend/api/assembly.py:2089`, `:2137`, `:2597`; `frontend/src/ui/feature_log_panel.js:1420`; `frontend/src/ui/edit_feature_popover.js:47`.

### F3 The dependency graph is too narrow for the proposed guarantee

`analyze_dependents` grows a removed-ID set from **added** objects. `reconstructable` is explicitly ignored. Structural extraction sees references in added/modified output objects, not necessarily everything the command read. The collection inventory omits, among others, lattice frames, nanoparticles/conjugations, duplexes, overhang bindings, and nucleotide transforms. `_object_refs` even has an OverhangBinding handler although the normal ID collection scan does not enumerate that collection.

Examples needing new coverage: shortening a helix without deleting its ID; changing a domain index or reference site; editing the deformation used by a continuation; removing an item that influenced a global routing choice; adding a candidate to a region queried by a later feature. Deletion/absence and collection membership are dependencies too.

**Required:** typed references, property/interval and collection reads, explicit creates/modifies/deletes, stable output identity and cardinality checks. Unknown contracts remain conservative. Never advertise independence based only on a recorded output diff. Track both referenced features and resolved entities; resolve against the correct historical state, not just current cluster membership.

Source: `backend/core/feature_dependencies.py:49`, `:89`, `:134`, `:245`, `:292`.

### F4 Mutation boundaries do not yet provide uniform isolation

Major mutations restore design/undo/redo when the callback raises, but subsequent reconcile, encoding, and validation work is outside that callback exception guard. Minor mutations push undo and clear redo before calling `fn`, without the same general exception rollback. These are transaction failure-window findings; fault injection must establish observable failures before fixes are made.

Several assembly replay branches install a candidate into live `assembly_state`, call a route, then restore the previous object in `finally`. Called routes can change revision/undo and other state. Restoring only the assembly object is not a complete isolated evaluator. `_replace_instance_design` writes a source file before updating the assembly; a background verifier must never use this path.

**Required:** pure candidate execution plus one commit adapter. Roll back all transaction-owned state on any failure; validate before publication; compare expected revisions at commit. Assembly transactions need source revision checks and a defined atomic publication protocol for shared source files. Capture immutable inputs under a short lock and do heavy work outside it. Resolve filesystem changes only during authorized commit, never during replay validation.

Sources: `backend/api/state.py:675`, `:819`; `backend/api/assembly.py:1400`, `:1473`, `:1551`, `:2137`; `backend/api/assembly_state.py:202`, `:339`.

### F5 Some authoring paths bypass feature recording

Confirmed examples: `routes_duplex.create_duplex` commits a changed duplex collection with `set_design` and no new feature; `headless_build.materialize_duplex_cluster` directly commits derived cluster state; `headless_build.place_primitive` uses snapshot plus silent replacement. PDB import merges commit a replaced Design without a general import command. The instance-design PATCH route accepts complete design JSON and persists it.

Direct setters are not all defects: camera poses, annotations, file navigation, history restoration, scratch sessions, manually constructed log entries, and protected loadouts have different semantics. `set_design` alone is not a sufficient enforcement point; in-place mutation, silent setters, source-file writes, assembly mutations, and reloads must also be classified.

**Required:** assign every mutation path a category: feature command, imported asset, history navigation, display/document metadata, physical result, or internal candidate. Strict mode rejects unclassified authoritative writes. File import/replacement recomputes trust and may load an unverified draft; it must not inherit a green badge from supplied JSON. Preserve users' ability to save drafts.

Sources: `backend/api/routes_duplex.py:178`, `backend/api/headless_build.py:1026`, `:1750`, `backend/api/routes_design_interchange.py:34`, `backend/api/assembly.py:1430`; complete candidate call-site list in `inventory.json`.

### F6 Generated native labels are not sufficient evidence

`generated_commands.ordinary_entries` is a useful compiler into ordinary feature rows. However, generated nick recording currently supplies `lambda d: after` to `fine_routing`, and the construction consistency assertion compares helices/strands only. Other kinds retain recorded snapshots and version-2 provenance. This does not prove their saved parameters regenerate their complete effects. Version-1 generated histories still have an active specialized editor/rebuilder.

**Required:** generated commands execute the same registered builders as manual commands, with complete authoritative-state comparison. Preserve grouping/provenance outside semantic parameters where possible. Avoid introducing a universal arbitrary-Design or arbitrary-Python command. Keep version-1 reads/edit compatibility until migration tests demonstrate equivalence.

Sources: `backend/api/generated_commands.py:21`, `:140`; `backend/api/generated_history.py:204`, `:315`; `backend/api/crud.py:8402`.

### F7 Field ownership needs one explicit contract

Part child diffs currently cover 11 collections, dependency extraction covers a different set, and `_topology_substitute` covers another. Assembly diffs compare instances/joints only, although assembly mutations affect more collections. The diff decision uses instance churn, not a general proof that changed fields are representable. Verify large-assembly revert for changes to bindings, groups, belts, duplexes, and other non-instance/joint fields before broadening use.

Define the authoritative projection once. Below is the proposed disposition of all 47 Design and 26 Assembly fields; mixed fields need nested classification rather than wholesale exclusion.

### F8 Historical edits have incompatible failure policies

Snapshot deletion can request cascade and then rebuild/subtract. Routing-child deletion can defensively apply later recorded diffs and report warnings after commit. `_rebuild_deformed_continuations` catches some replay failures and takes saved post-state. Assembly seek can return current state when old payloads are absent. These compatibility behaviors must never yield a verified regeneration result.

**Required:** shared feature statuses (`valid`, `failed`, `blocked`, `suppressed`, `unverified`) and document verification freshness (`pending`, `current`, `stale`, `cancelled`). Preserve independent branches; first failing input explains dependent blockage. Error results contain feature IDs, parameter/reference paths, affected scope, and available repair actions. Draft mode can preserve broken definitions; strict mode cannot commit an invalid final candidate. Deletion preview is bound to the document revision, so a stale cascade decision cannot delete new work.

Sources: `backend/api/crud.py:7549`, `:8050`, `:8995`; `backend/api/assembly.py:1990`.

### F9 Cross-document sources and assets are part of the proof

Assembly instances can share mutable file-backed source parts. Validating the assembly history while its source files change is insufficient. Source path alone is not provenance, and copying a complete source into a snapshot does not grant native editability.

**Required:** source revision/content manifest, reverse source dependencies, one validation per unique source revision, and explicit invalidation of every affected instance. Validate placement separately from source construction. Missing or changed external assets produce an unresolved status. Asset retrieval must not be a hidden network operation during drag/seek or verification. A native reference part retains its own feature history; a genuine import is labeled as such.

Reuse document context, design identity, existing source caches and shared-source refresh behavior; do not give every instance its own duplicate verification worker.

## Architecture and performance contract

The new dependency system must reduce repeated work rather than adding another full-design scan to every edit.

1. **Registry and receipt:** each successful command produces normalized parameters, stable output identities, a read/write/delete summary, and revision/version metadata. Reconciliation and automatic ligation consequences belong to the same receipt. Unknown operations invalidate proof conservatively.
2. **Incremental index:** maintain producer/consumer and reverse-dependency indices once per recipe revision. Use entity/property and collection keys. Traverse only affected descendants; collection-wide algorithms may legitimately invalidate a large suffix. Worst case remains full rebuild and must be visible/cancellable.
3. **Two revisions:** distinguish authored-recipe/content changes from visual/cursor changes so camera movement and history browsing do not repeatedly invalidate a verified recipe. Scope active-prefix checks by cursor/subcursor without certifying an unchecked tail.
4. **Two evaluation paths:** preserve snapshot/diff restoration for browsing. Use registered-command evaluation for proof and changed inputs. Verified intermediate results can accelerate later work, but a full audit bypasses output caches to detect hidden inputs and stale cached state.
5. **Bounded background work:** coalesce superseded jobs, validate an immutable revision, prioritize foreground edits, and discard stale results. Bound worker count, retained states, payload bytes, and task lifetime. Cancellation must work between features; long builders require cancellation points. One task must not serialize multiple full Designs unnecessarily.
6. **Fast commit:** reuse a successfully prepared candidate and its receipt; do not run the builder again on confirm. Publish under expected-revision checks, including source revisions. An agent transaction may take time; show progress and keep the viewport responsive. Never mark a still-running audit green.
7. **Compact response:** return summary/status deltas and paginated diagnostics. Do not add full snapshots, entity-reference graphs, hashes of multi-megabyte JSON, or repeated full audit bodies to ordinary responses.

Do not put validation in `requestAnimationFrame`, pointer-move callbacks, geometry generation, ordinary GET serialization, or every seek request. Do not hold the session lock while replaying, decompressing history, hashing assets, or generating geometry. Existing validation costs should be measured separately from new costs so work is not accidentally duplicated.

Preserve `feature_seek_preview.py`'s revision/source binding, bounded preview storage, and preview/commit reuse; the client's history-body acknowledgement and slim responses; targeted geometry batching; the small-log path; and assembly diff/skip-pre/source deduplication. A history cache is an optimization, never an alternate authority.

### Measurement and regression gates

No new performance timings were collected in this audit. Existing `docs/feature_evaluation.md` and its benchmark JSON provide historical A/B evidence, not current-machine acceptance numbers. Rebaseline before changing the hot path.

| Workload | Required measurements | Regression gate |
|---|---|---|
| Small manual edit and no-op edit | Input-to-paint, request p50/p95, CPU, lock hold, bytes | Paired baseline/candidate; proposed gate: investigate/reject p95 growth exceeding both 5% and 5 ms, subject to baseline noise characterization |
| Drag, sweep preview, move/rotate | Frame times, dropped frames, first preview, confirmation | Zero full audit/replay invocations per pointer event/frame; no new blocked editing interval beyond candidate preparation |

Run benchmarks through `just validate-safe`, serially with tests/builds. Use Archive-backed scratch for large outputs; never mutate workspace designs. Retain exact baseline commit, fixture hashes, machine conditions, cold/warm runs, repeated alternating A/B samples, and p95 plus peak memory. Existing scripts: `benchmark_feature_evaluation.py`, `benchmark_feature_scrubbing.py`, `benchmark_assembly_fk.py`, `benchmark_assembly_shared_index.py`. ## Implementation phases and exit criteria

### Phase 0 Audit and baseline

This source inventory, coverage matrix, findings, cleanup ledger, and regression plan are complete. Before application changes, capture current benchmarks on representative fixtures and add reproductions for the assembly allowlist mismatch, non-instance/joint assembly diff changes, minor callback/postprocessing failure windows, and an unlogged duplex edit. Establish nested-field ownership, asset policy, and exact UI budgets. Runtime route tracing and fault injection remain implementation-entry work; this audit does not claim every route has been exercised.

**Exit:** source inventory reconciled with critical runtime paths; correctness/performance fixtures and baseline recorded; each candidate cleanup has owner, compatibility rationale and test. No strict gate yet.

### Phase 1 Registry and transaction isolation

Add cohesive modules such as `core/feature_registry.py`, `core/feature_contracts.py`, and `api/feature_transactions.py` (names provisional). Wrap existing supported builders first. Centralize capabilities and status schemas; classify mutation routes and document fields. Extract pure assembly builders from live-route replay. Make all commit failures restore design, undo/redo and revision; make source publication transactional. Implement deterministic IDs/version metadata for new commands. Perform the small dead/no-op cleanups with their contract tests.

**Exit:** current behavior retained; invalid candidate never leaks state or filesystem effects; capability declarations match implementations; no interactive timing regression. Legacy adapters remain explicit.

### Phase 2 Read-only verification and incremental dependencies

Add an opt-in report/CLI and API over registered commands, authoritative-state comparison, typed dependency indices, revision-bound results, and bounded background execution. Report unsupported rows as unverified. Capture input/effect receipts at recording time to avoid future history-wide snapshot decoding. Add a compact passive history status in desktop/selected-part/assembly/VR hosts after backend semantics stabilize. No blocking on every edit and no claim that an unchecked prefix/tail is valid.

**Exit:** an out-of-log change is detected; failed/blocked features are explained; cached and cold verification agree; cancelled/stale tasks cannot publish; viewport and scrub benchmarks pass. Unsupported legacy documents remain usable.

### Phase 3 Complete native DNA command coverage

Implement families in this order: six existing primitives plus stable references; remaining helix/strand/domain/nick/ligation/crossover operations; loop/skip/sequence and explicit pose/grouping controls; auto-scaffold/staple/routing and pattern commands; sweep attachments and joins. Replace generated nick/result shortcuts with registered execution. Promote each family independently after complete inputs, deterministic IDs, downstream edits, GUI parameter coverage, and topology/reconcile parity are demonstrated.

**Exit per family:** empty-root cache-free replay equals authoritative state; deleting/changing a producer correctly rebuilds consumers; independent work survives; every meaningful parameter has an editor or explicit limitation. Numerical/physical constants and topology rules remain unchanged.

### Phase 4 Assemblies and external assets

Complete instance/connector/joint/group/gear/belt/polymerization/binding/duplex coverage; pin unique part sources and validate source histories once; fix diff field coverage. Add explicit protein/PDB/aptamer/nanoparticle/source-asset commands, attachment semantics and asset availability diagnostics. Classify relaxation operations into authored pose controls versus protected physical results; do not relaunch simulations for routine verification. Preserve undo and save/reload across shared-source edits, and distinguish reference imports from agent-authored native construction.

**Exit:** mixed part/assembly histories replay without touching live sessions or files; source revisions are checked atomically; large repeated-source benchmarks pass; reference assets have truthful editability labels.

### Phase 5 Repair and draft workflows

Extend the existing dependents dialog with revision-bound impact previews, explicit cascade, keep-broken draft, and reference replacement. Show root failures and blocked descendants; make last successful geometry visibly distinct from current state. Use the same candidate for preview/commit. Desktop, selected assembly parts and VR share diagnostics/actions; add discoverable VR tours. Preserve one-step undo for confirmed transactions and save invalid drafts.

**Exit:** users can diagnose, repair, cancel, undo, reload and continue editing without hidden geometry, lost selections or modal spam. No status badge means physical validity. App/VR host checks completed.

### Phase 6 Strict agent commits and legacy retirement

Expose atomic command batches under a document policy: agents cannot submit arbitrary state/snapshots or downgrade policy; generic setters/import/load cannot retain a forged verification badge. Strict edits require a verified starting recipe or an explicitly established import boundary, registered commands and a valid final candidate. Humans may save invalid drafts. Reject unsupported commands with actionable capabilities, not a silent fallback. If agents can modify server code/files, application policy alone is not a security boundary; trusted-service deployment is required for adversarial enforcement.

Retire duplicated dispatch and compatibility glue only after their replacements cover persisted fixtures and all relevant tests. Keep adapters for unconverted legacy documents; migration is explicit and reversible. Preserve Python orchestration through the command API.

**Exit:** bypass attempts fail across design, assembly, generated, headless, import and shared-source routes; valid multi-command transactions produce fully editable histories; all correctness/performance gates pass. Enforcement cannot be disabled by an agent-controlled request field.

Reuse existing tests as regression evidence, not proof of new semantics: `test_feature_dependencies`, `test_feature_log_snapshot`, `test_feature_log_clusters`, `test_fine_routing_diffs`, `test_feature_evaluation`, `test_feature_seek_preview`, `test_feature_log_edit_core`, `test_assembly_feature_log_actions`, sweep/pattern/generated tests, and frontend history-body merge/revision/scrub/VR tests.

Add behavior tests for:

- Cold replay with all disposable outputs removed; authoritative-state mismatch; parameter and asset tampering; unsupported command and missing asset.
- Extrude removal, transitive dependent cascade, unchanged-ID shortening, collection query invalidation, deleted/recreated IDs and reordered domains.
- Randomized histories comparing incremental evaluation with independent full replay; do not merely compare two paths sharing the same incomplete contract.
- Each failure window before/after builder, reconcile, diff, encode, validate and publication; unchanged undo/redo/revision/files on failure.
- Preview/commit races; shared source mutation during audit; undo/redo/branch/cursor invalidation; late background result discard.
- Generated construction through real commands; imported asset cannot conceal native editable construction under strict policy.
- Assembly changes outside instances/joints at diff threshold, and mixed full/diff/skip-pre legacy histories.
