Read-only closure review, October 15, 2026. This is a finite delivery map, not a
new claim that every registered kind or legacy receipt regenerates. Assemblies
remain outside the agreed scope. Existing molecular builders and constants stay
unchanged; each new adapter must preserve their complete admitted output.

## Next P4 checkpoint: pending nanoparticle connection candidates

Implement the existing `nanoparticle-connection-version-create`, `-patch` and
`-delete` kinds for **unapplied candidates only**. The visible overhang panel
creates these before applying them. This closes an ordinary structural-authoring
gap without calling `fitting_geometry`, relocation or relaxation.

Create records exact particle/conjugation/strand/target-overhang identities,
explicit version identity/time/name and direct variant, with strict
`_proof_version=1` and `nanoparticle_connection_version=1`. `applied` must be
false. Patch initially renames an unapplied candidate; delete removes it.
Admission requires no associated duplex, relaxation result or retained constraint
state, one unambiguous unbound thiol owner and a valid ordinary target. Do not
silently convert Apply/Unapply into metadata-only operations.

Use a new pure API contract module and thin existing route adapters. Reuse the
native endpoint/polarity rules and typed reference inventory. The existing
`part_thiol_commands.resolve_owned_handles` can validate a complete unbound owner
selection, but its replacement/deletion incoming-reference policy is not a
connection-create policy; do not blindly call its removal guard. Preserve the
part topology dependency barrier because common executor postprocessing still
has broader effects. No output geometry, source reconstruction or new numerical
pin is needed for these metadata operations.

Exit: native empty-root gold/graft/target → create/rename/delete cold proof,
exact input edits, missing/deleted producer diagnostics, unchanged unrelated
authoring, ordinary visible route parity, one atomic row/undo/revision, stale and
session-ABA rejection, and a bounded 1/16-handle route benchmark including retained
history. Final admission ceilings follow that measurement; existing global
capture/recovery limits do not change. This checkpoint alone does not qualify
connection application.

3. **P6 ownership and responsiveness:** implement the already reviewed exclusive
   immutable strict revision storage, persistence/transition/retention boundaries,
   then qualify actual HTTP batch capture/evaluation/publication with concurrent
   light reads. The public batch gate remains closed until this passes.
4. **P6 catalog and policy:** extend the finite public native command catalog to
   the admitted P3/P4 families; imports require explicit host policy and retain
   imported provenance. Close all strict read/write routes against that catalog.
   Only then add revision/engine/source-qualified replay reuse; caching is an
   optimization, never the source of authority.
5. **Final regression and pruning:** reconcile the current registry, route and
   generated compiler inventory; retain legacy recovery readers but remove only
   unreachable authoring paths proven unused. Run the required existing broad
   backend/frontend suites and measured ordinary-edit/seek/viewport regressions.
   Record environment/baseline failures separately from new regressions.

Every row above has a bounded exit. A refused oversized or unknown operation
remains unverified with an actionable reason; it is not silently recategorized as
an assembly or a native success. No new command becomes public merely because its
pure builder exists. This ordering completes structural provenance first, then
bounded attachment/import coverage, repair UX and enforceable agent construction.
