## 1. Definition of done: per-tool contract

The product goal is SolidWorks/Onshape-style parametric editing. A tool —
**Bend, Twist, Extrude, Sweep** — is *done* when its production gate(s) are ON
and core items C1–C9 pass in the running app on a representative design.
Internal proofs (replay equality, receipts, private routes) are means, not exits.

| Item | Requirement |
|---|---|
| C1 Create | Every existing entry point (toolbar, sidebar, context/end menu) creates the feature with live preview, exact Cancel and a single Apply. |
| C2 Edit | Parameters of any historical instance can be edited; Apply regenerates everything downstream. Where the tool already has a live preview it must be isolated from canonical state; a tool whose existing editor is a modal form without live preview (currently Extrude) passes C2 without one, and live preview for it is follow-on scope. |
| C3 Regenerate | Post-Apply state equals independent cold replay from the explicit root, including at least one downstream topology-changing feature (nick, ligation, autostaple or routing) so helix/strand/domain identity survives. Identity rules come from existing native contracts; any uncertainty → ask the user. |
| C4 Failure | When an edit makes a downstream feature unregenerable, the earliest failing feature shows an error with its reason, descendants show blocked, and nothing fails silently. Use and document the existing behavior (refuse-with-reason or commit-with-error-state) in ≤ 5 lines in the tool's plan; do not invent new semantics. If no edit of this tool can make a descendant unregenerable, record that with the evidence; C4 then passes. |
| C5 Dependents | Deleting or changing an upstream entity this tool references lists the dependent features before commit (existing dependents dialog). |
| C6 Persistence | One-step undo/redo; save/reopen; reopened file regenerates identically. |
| C7 Rollback | Creation and editing behave correctly with the history cursor mid-log (insert at cursor, or refuse explicitly). |
| C8 Latency | All three §3 budgets measured on the representative designs; passes when every miss is ≤ 2×. |
| C9 Legacy | This tool's obsolete preview/apply path is removed, or proven unreachable, in the same task that flips its gate. |

**Follow-on contract (separate milestone, after all four tools are done; not a
gate-on prerequisite):** suppress/unsuppress, reorder within dependency
constraints, reference-repair UI, parent/child dependency viewer.

**Bend and Twist share their gates, so they are one gate unit:** flip only when
both pass C1–C9; they count as two tools done at that moment.

Known gates: Bend/Twist — `ISOLATED_DEFORMATION_HISTORY_ENABLED`,
`ISOLATED_DEFORMATION_CREATION_ENABLED` (`frontend/src/app/feature_editor.js`),
`DEFORMATION_PREVIEW_ENABLED` (`backend/api/routes_part_deformation_preview.py`).
Sweep — `SWEEP_HISTORY_EDITOR_ENABLED`, `SWEEP_PREVIEW_ENABLED`. Extrude — identify
its gate(s) or record that its history editor is already reachable. Flipping a
gate for a tool that passes C1–C9 is authorized by this contract; it needs no
further rollout qualification. Do not flip unrelated gates.

## 2. One lifecycle

Each tool keeps the preview/apply lifecycle it already uses (Bend/Twist: the
`part_deformation_preview_sessions` publisher; Sweep/Extrude and native
transforms: the immutable geometry host). The "sealed" historical-preview path is
not required for any gate-on, and further sealed-path work is excluded. Do **not** add another host, queue,
session/lease type, "sealed"/admission/observation layer, storage format or
capability endpoint. If one seems necessary, stop and report to the user with
the evidence instead of building it.

## 3. Latency budgets (provisional defaults; the user may revise)

Representative designs: copy an existing workspace design (for example
`workspace/6hb_e_test.nadoc`) plus one larger existing design into scratch;
never mutate the originals. Record which files and their sizes.

| Interaction | Budget |
|---|---|
| Preview update after a parameter change (request + render) | p95 ≤ 500 ms |
| Apply → adopted display | ≤ 3 s small design, ≤ 10 s large design |
| Cancel | ≤ 200 ms, no canonical request |

A miss of up to 2× does not block gate-on: flip the gate and record a
performance task. A miss of more than 2× → performance task first.

## 4. Test-harness rule

Requests unrelated to the tool under test (simulation, jobs, engines, library,
VR, animations, and so on) are stubbed or allowed **in the test harness or
fixture app only**, preferably by stubbing the
route (for example a Playwright `page.route` fulfil) rather than filtering console
messages. A console filter, if unavoidable, must match exact unrelated route URLs
and never a message pattern that could hide tool errors. Never add or change production code to make unrelated
requests pass a harness. Console strictness applies to errors from the tool's own
routes and UI; unrelated noise is fixed in the harness.

## 5. Stop-loss and scope

- The handoff header carries `Sessions since last gate flip or milestone close: N`.
  It was reset to 0 when this contract was adopted. **Only a production gate flip
  resets it** (a milestone close alone does not). Every other session ends with
  N+1, including sessions that stop to ask the user, except the stop-loss
  report session itself, which leaves N unchanged.
- One task per session. While waiting on a user answer (scientific question,
  stop-and-ask), the session may continue other contract items of the same tool
  that do not depend on the answer.
- At most one open deferred performance task per tool; a second miss blocks the
  next gate flip until one is resolved.
- At **N = 3**, do not select or start a successor: write a short blocker report
  in the handoff and ask the user.
- A prerequisite outside Bend/Twist/Extrude/Sweep → stop and ask; do not build it.
- Successor selection is a ≤ 15-minute gap check against C1–C9, not a re-audit.
  Pick the task that most directly closes the nearest tool's
  remaining C1–C9 items toward gate-on. Finish one tool before widening test
  matrices across tools. Bend/Twist is expected to be nearest.

## 7. Commits (user authorization, October 18, 2026)

At the end of each session, commit the session's work locally:

- Stage by explicit path only (never `git add -A` or `git add .`). For a file that
  mixes your hunks with another session's, stage only your hunks
  non-interactively (write the hunks to a patch in scratch and `git apply --cached`
  it); if that is impractical, leave the file uncommitted and list it. An
  uncommitted hunk does not by itself make the task undelivered.
- Commit a file only if every uncommitted hunk in it belongs to the
  feature-history overhaul (this or earlier S-sessions). Leave files that mix in
  other sessions' work (VR, memory hygiene, CPD, other areas) uncommitted, and
  list them in the handoff.
- The first session under this contract may include the uncommitted S01–S53
  overhaul backlog under the same per-file test, listing the files in the commit body.
- Message style: `history: <summary>`, plus any attribution lines your harness requires. No push, amend, rebase or hook bypass.
- Never use `git stash`, `reset`, `restore` or `checkout -- <path>`.
