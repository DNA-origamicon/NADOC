# Experimental small-protein free import — ordinary route gated

The ordinary `POST /api/design/import/pdb-auto` route retains its existing legacy behavior. `routes_design_interchange.NATIVE_FREE_IMPORT_ENABLED` is a server-owned constant set to **False** because retained-state performance qualification failed; no request or environment field enables it. Native regression fixtures and the diagnostic benchmark explicitly enable and restore the gate. The existing pinned command APIs remain available independently. This document describes the experimental path, not a completed ordinary import migration.

When explicitly enabled for qualification, the free-placement path prepares a bounded native suffix: `protein-import` records the original UTF-8 PDB descriptor and filtering choices; `protein-attach` records the chosen free placement and conjugation atom. Both rows, their original bytes, and the session-library cache entry publish together with one undo and one revision. The parser runs once during preparation. An actually absent document receives a new empty recipe root; existing rootless or broken histories keep their original provenance and diagnostics. The response explicitly reports `native_suffix` and `whole_design_verified: false`.

The synchronous UI workflow does not prove its entire existing prefix. Preparation uses the existing command builders, source resolver and recovery encoder. It cannot reconstruct missing source bytes from parsed atoms or silently restore a missing/corrupt existing declaration when the same PDB is uploaded again. An unrelated already-broken descriptor remains diagnosable and does not prohibit this independent suffix. Repeated source bytes share one portable source record; distinct import actions retain distinct asset and placement identities. Library-only imports and placement of an earlier cross-document library entry are unchanged and remain outside this slice.

Admission remains 250,000 source bytes, 1,000 original ATOM/HETATM records, and 4,000 parsed bonds. There is no truncation. The two new rows reserve space within 2,000 flattened history rows, and their recovery pairs share the existing cumulative 8 MB recovery allowance with retained history. Authoring capture and retained presentation/proposal metadata share one original cooperative 25 ms deadline and the ordinary 30,000-node / 2 MB allowance. Retained metadata additionally has a conservative 10,000-node / 256 KB sublimit. These are admission budgets, not hard latency ceilings. The private final candidate must also fit the ordinary authoring allowance after metadata charges; no global capture limits change.

This first ordinary path requires default retained physical fields: no stored loadouts, simulation projects, atomistic reference or active-loadout metadata. Such state needs a later separately qualified publication/undo scope. Unsupported source/state is selected before native parsing: a recipe-backed part gets an explicit admission error; rootless/absent-document compatibility can use the legacy path with `legacy_unverified` provenance. Once native preparation starts, failure never falls back to a legacy mutation.

The host compares the captured document object and session revision again before publishing. Cancellation/disconnection, stale work, source failure, recovery refusal, response formatting failure and library insertion failure leave the original document and library unchanged. Candidate response formatting explicitly bypasses legacy response-time cluster normalization. Both new recovery pairs reach the browser cache; previous rows stay slim and the existing skip-geometry policy remains effective. Non-authoring metadata and the current repair draft are preserved at publication; native candidate source additions remain authoritative.

`part_protein_import_recording` narrowly reuses the private bounded `_Copier` from `part_repair_capture` for retained metadata. It rejects hidden/extra model state and consumes the remaining original capture deadline rather than obtaining another time budget. Promoting that copier to a shared capture utility is follow-up cleanup once both callers settle.

`tests/test_native_protein_free_import.py` covers actual HTTP import, independent parser parity, two rows/one publication, cold proof ignoring recovery/library, parameter edits and dependency cascade, original mixed PDB bytes, retained proposals, stale/cancel/fault atomicity and refusal before fallback. Existing protein lifecycle tests now distinguish source import from independent placement. `scripts/benchmark_protein_free_import.py --repeats 30` measures actual HTTP, parser count, capture/publication locks, concurrent lightweight requests, cold proof and the source/atom/bond boundaries without writing workspace artifacts or changing scientific formulas.

The first serialized route test stalled because the initial publication wrapper reacquired the non-reentrant state lock through `state.set_design` and the public library setter. The parent terminated only that owned pytest process after approximately 90 seconds; it did not complete a test. Publication now calls the existing lock-owned `publish_replacement` primitive and a lock-owned library assignment within the rollback envelope, preserving the ordinary loadout/CPD guards. The global lock remains unchanged. A deterministic test wrapper raises on a same-thread second acquisition instead of hanging. Captured session identity and document context additionally reject close/reopen ABA cases even when the source object and revision match; stale publication does not recreate a closed session. The first rerun passed 35 cases; one annotation fixture exceeded its individual model limit before reaching the route, and was replaced with an aggregate of valid annotations.

The corrected serialized run passed 124 tests: 36 free-import, 72 existing protein and 16 pinned-source proof cases. The first 30-repeat benchmark attempt then stopped at the second fixture because two `Vec3` constructors omitted required coordinates; it produced no complete qualification output. Both fixture constructors now supply x/y/z, and the harness retains completed-case results plus explicit exception metadata on future failures, with a nonzero exit and `completed: false`.

The corrected first complete benchmark, retained in `protein_free_import_benchmark_p4.json`, exited 1: 28/30 1,000-atom imports succeeded, with two atomic post-parse candidate-capture refusals; the other four cases had 30/30 expected outcomes. Each import parsed once, publication-lock p95 stayed at or below 0.279 ms, and lightweight-request p95 at or below 9.55 ms. The atom-boundary source-capture p95 was 1.35 ms, while route p95 reached 263.44 ms. This is failed boundary qualification, not permission to retry or increase limits. It also did not measure populated protein-history publication, so its small commit-lock figures cannot establish that broader claim.

The approved narrow efficiency change extends the existing exact nine-scalar `ProteinAtom` memo-copy specialization from nanoparticle authoring to `protein_assets`. Every atom and field keeps its node/byte charge; aliases remain internal to the copied field, mutable containers remain isolated, and subclasses, extra/private/cached state, changed schema and non-scalar fields fall back to ordinary deepcopy. Candidate admission remains mandatory, with the same 25 ms cooperative / 30,000-node / 2 MB budgets and no retries or GC changes. The parent reported 26 copy-parity, 36 native free-import and 65 coating-scope tests passing after this extension.

The harness now also creates retained recipes through actual HTTP imports before measurement: same-source reuse, a distinct new source, twenty valid annotations plus a camera pose and repair proposal/source bytes, eight small imports followed by a ninth, a retained 1,000-atom asset followed by another, and an explicit aggregate 3,000-atom refusal. It measures populated capture/publication locks, candidate admission, concurrent requests against an idle baseline, full retained source/feature/metadata equality, and exact undo/redo outside timing. A setup refusal is reported as incomplete qualification; no fixture bypasses native admission. `--suite boundaries` and `--suite retained` permit separate evidence files without replacing the first completed failure report. No populated-history performance claim is established until those runs complete.

The optimized expanded run is retained separately as `protein_free_import_benchmark_optimized_p4.json`. It exited 1 and was incomplete: ten cases were reported before the aggregate-refusal fixture's second setup import itself refused. The 1,000-atom case and retained same/new-source cases each passed 29/30; eight prior imports followed by a ninth passed 27/30; retained 1,000 plus new 1,000 passed 27/30. Both pre-parse source captures and post-parse candidate captures hit their deadlines. Eight-import capture p95 was 50.72 ms; successful publication also had isolated approximately 47 ms stalls. This does not establish stable ordinary publication and is why the gate remains closed. Periodic garbage collection is a hypothesis, not a measured explanation in that report.

The next diagnostic harness version observes generation-specific `gc.callbacks` intervals and their overlap with source capture, candidate capture, publication and native parsing. It never disables/forces collection or changes thresholds. `--case` allows a targeted run, and candidate metrics now use the route's actual `native_candidate_admission` key (the earlier aggregate was empty). All earlier reports remain intact. Replacing the discarded final candidate copy with exact allocation-light node/byte admission is a separately approved next design step, **not implemented in this checkpoint**; source isolation, atomicity and ordinary proof limits must remain intact.
