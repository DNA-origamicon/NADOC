# Mobile gold–thiol–DNA in oxDNA

`DNA2GOLD` is an isolated, CUDA-only extension of pinned upstream oxDNA
`8028cf33b3cba12992b771156085fa54879f50cd`. It simulates translating and rotating
spherical gold cores, body-fixed grafts, and normal oxDNA2 DNA. Gold is never
immobilized. The first supported chemistry is an **effective permanent short
linker** for the existing `direct_thiol`/C3 design preset.

The engine also supports an experimental [rigid streptavidin–biotin–DNA coating](oxdna_mobile_strep.md).

## Use

Build with `bash scripts/build-oxdna-mobile-gold.sh` (CUDA toolkit required;
`OXDNA_CUDA_ARCH` defaults to 75 for the local RTX 2080 SUPER). The engine is
isolated under `~/.local/share/nadoc/engines/oxdna-mobile-gold/current/bin/oxDNA`;
`NADOC_GOLD_OXDNA_BIN` overrides it. Normal DNA and PEG installations are unchanged.

Author gold and direct-thiol handles in Conjugate Manager and connect handles to
origami overhangs through the existing connections workflow. Relaxation preparation
automatically exports the core/graft records and selects CUDA MD for **every**
stage, including replacement of the usual CPU MC stage. Append production, or
use a free-solution Run child, to continue with the same cores and grafts.
CPU fallback is rejected. Missing or unsupported chemistry is an error.

`mobile_gold.dat` contains engine parameters and immutable topology indices;
`mobile_gold.json` records strand/core identity and provenance. Core particles
are appended after DNA using reserved type 499, without fictitious base pairing
or backbone bonds. Native trajectory rows preserve center, orientation,
translational velocity and body angular velocity. Core angular columns use
angular velocity (the ordinary unit-inertia DNA convention); the core integrator
and thermostat explicitly account for its non-unit inertia. Restarts retain all
these values. Display/trajectory frames carry separate `__gold__` identities;
core transforms share DNA's periodic unwrapping and display alignment.

The review artifact `experiments/mobile_gold/ws/Mobile_gold_review.nadoc` contains a 6,012-nt
origami with one terminal staple grafted to a 10 nm sphere. This checks force
transmission into an origami; it is not a demonstration of spontaneous hybridization.
Its short relaxation/settling job is a numerical smoke example, **not an equilibrated
origami ensemble**. Separate native tests use strands generated by the actual
conjugation builder, with both 5′ and 3′ grafts.

## Mechanics and units

For core center R, orientation Q, and body-fixed sulfur site s, the graft is
`a = R + Q s`. For the terminal nucleotide backbone site b:

`U_link = k/2 (|b - a| - l0)^2`.

The GPU computes equal/opposite forces plus `r × F` torques on **both** rigid
bodies. The DNA backbone site includes the oxDNA2 asymmetric-groove offsets;
this is not a force on the nucleotide center of mass. The gold graft remains
fixed to its material surface rather than sliding around the center.

Exclusion uses a one-sided harmonic overlap penalty, between a DNA center and
`R_core + clearance`, and between pairs of gold spheres. Thus the core is a stiff
soft sphere, not an exact hard constraint. Seed preparation rejects DNA inside
the physical core and overlapping cores. Finite penetration during dynamics must
still be monitored, especially under strong imposed loading.

The dedicated GPU kernel checks DNA–core contacts in O(N_DNA N_core), separately
from DNA's short-cutoff neighbor list. Only grafts and contacts accumulate core
forces atomically. This avoids expanding every DNA neighbor list to the gold
particle diameter. The initial implementation caps the number of cores at 64.
No per-step GPU→CPU force transfer is used. Both edge and non-edge DNA list modes
and float/mixed integration have native force checks.

## Parameter basis and numerical selection

| Quantity | Current value / basis |
|---|---|
| Core radius | Authored gold diameter / 2 |
| Core mass | Bulk Au density 19.3 g/cm³; nucleotide mass unit 315.75 Da |
| Core inertia | Uniform solid sphere, `I = 2 m R² / 5` |
| Core diffusion | Bare-sphere Stokes–Einstein / Stokes–Einstein–Debye at 298.15 K, water viscosity 0.890 mPa s; nominal oxDNA time unit 3.03 ps |
| Linker rest extension | Existing authored spacer, normally 0.7 nm; restricted to 0.3–1.5 nm for this short-linker model |
| Linker stiffness | 10 oxDNA energy/length² units, approximately 571 pN/nm |
| DNA CM surface clearance | 0.4 nm, an isotropic steric approximation |
| Exclusion stiffness | 100 oxDNA energy/length² units |
| MD timestep | At most 0.002; tested against 0.001 and 0.004 |
| DNA thermostat | Langevin, diffusion coefficient 2.5 in simulation units |
| Core thermostat | Mass/inertia-aware exact Ornstein–Uhlenbeck velocity update with independent translation/rotation noise |

The linker stiffness is a **numerically selected effective restraint**, not an
atomic Au–S stretching constant or an experimentally fitted C3 compliance.
At 300 K it implies a radial fluctuation scale near 0.085 nm before sterics and
orientational entropy. Sweeps at k=3,10,30 support k=10 as a practical middle
setting with dt=0.002. The 0.7 nm preset is retained as an explicit structural
assumption, not inferred from the initial strained seed. `parameters_qualified`
remains false in the manifest: numerical stability is not physical calibration.

Literature supports using coarse-grained grafted cores and flexible DNA, but does
not by itself establish these exact linker/clearance parameters:

- [Fochtman, 2017](https://scholarworks.uark.edu/etd/1926/) describes a GPU oxDNA
  extension for DNA-functionalized gold nanoparticle building blocks.
- [Vargas-Lara, Starr & Douglas, 2022](https://doi.org/10.1039/D2NA00377E)
  studies grafted DNA layers and emphasizes that effective hydrodynamic size
  depends on the corona. Our bare-core drag plus independent DNA drag is an
  approximation without solvent-mediated hydrodynamic coupling.
- [oxDNA configuration specification](https://lorenzo-rovigatti.github.io/oxDNA/configurations.html)
  supplies the 0.8518 nm length unit and oxDNA2 backbone-site offsets.

The former atomistic-linker comment cited `10.1038/ncomms13344`. That DOI actually
identifies an unrelated cardiac-arrhythmia paper. It was removed as linker evidence;
no Au–S parameters were taken from it.

Absolute diffusion kinetics, corona hydrodynamics, Au–S dissociation/exchange,
surface adsorption, charge transfer, electrode potentials, and specific Au–DNA
attractions are not qualified by this model. Alkyl/PEG/backfill, independently moving protein coatings,
additional field/surface elements and deposition branches are rejected for now.
Ordinary GPU DNA interactions remain oxDNA2; optional duplex relaxation traps
are removed for unrestrained production, while graft potentials persist.

The upstream host energy routines omit the custom long-range core kernel. Generated
inputs therefore disable misleading host energy output. The validation scripts
reconstruct the toy system's complete potential and mass-weighted kinetic energy.
Do not use stock CPU DNAnalysis for gold energy, virial or pressure analysis.

## Validation and cloud execution

See [the retained validation report](validation/oxdna_mobile_gold_2026-09-15.md).
Native mechanics checks, NVE sweeps, thermal sampling, generated-handle runs,
and the origami timing pilot ran on the local RTX 2080 SUPER. **RunPod spend: $0**;
the authorized cumulative cloud cap is $5, not a per-attempt allowance.

RunPod staging now uploads the custom sources, chooses a content-addressed gold
engine cache, rewrites the remote model path, and rejects CPU/mixed-model stage
chains **before renting a pod**. This staging path is unit tested, but no remote
gold execution has been claimed. Use the existing durable CampaignLedger and
pod lifecycle/watchdog for any cloud attempt; GPU-only applies to failed attempts
as well. The historical archive mount `/media/jojo/Archive` is absent on this
machine, so a future cloud fetch destination must be resolved before rental.

Reproduce native mechanics and sweeps:

```bash
.venv/bin/python -m experiments.mobile_gold.validate --output experiments/mobile_gold/ws/gold_mechanics_new
.venv/bin/python -m experiments.mobile_gold.sweep --output experiments/mobile_gold/ws/gold_sweep_new
.venv/bin/python -m experiments.mobile_gold.benchmark --source workspace/3x6Sq_oxDNA.nadoc --output experiments/mobile_gold/ws/gold_timing_new
```

All output directories are new and refused if already present. Benchmark sequences
must be defined; the unsequenced `18hb_fixture.nadoc` is not a valid native input.
