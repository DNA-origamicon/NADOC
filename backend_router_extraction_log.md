# backend router extraction log

Tracks the incremental decomposition of `backend/api/crud.py` (≈15.6k ln, 190 routes) and
`backend/api/assembly.py` (≈7.8k ln, 112 routes) via the loop in `backend_router_carveup.md`.
**One row per extraction, one commit per extraction.** Sibling of `main_js_extraction_log.md`, adapted for
the backend's two target shapes (FastAPI sub-routers + `backend/core` service helpers) instead of frontend
factories.

**Why this exists:** the in-repo precedent (`routes_loop_skip.py` = Refactor 10-F, `routes_camera_poses.py`
= 13-B) proved a route cluster *can* be lifted cleanly — but those were one-offs with no measured contract,
and crud.py kept growing anyway. This log measures whether each move is a *real* decoupling or just LOC
shoveling (see the carve-up's "anti-shovel contract"). A row that can't fill its justification column is a
shovel and gets reverted.

## Conventions — how to read the columns

- **`B` (back-import surface) is the headline number.** It is the count of distinct private (`_foo`) symbols
  the new `routes_<area>.py` imports back from its god-file. **Log before-B → after-B.** The shipped exemplars
  sit at B = 1–2. A router extraction ships only at **B ≤ 3**; above that, co-extract the helpers to
  `backend/core` or pick a cleaner cluster (carve-up → high-B playbook). `_design_response`-family imports
  count toward B but are the accepted shared kernel — they don't block.
- **LOC Δ is narrative, NOT the pass criterion.** A big crud.py LOC drop with B unchanged only *relocated* the
  problem. The pass criterion is **coupling (B) down OR business-logic-into-a-tested-core-fn up.** Report LOC
  as story.
- **"routes remaining in god-file"** is the LOC-correlated metric that actually means something (fewer
  concerns in the kernel) — track it instead of raw lines.
- **Verbatim vs adapted.** A router lift with **byte-identical handler bodies** is behavior-preserving by
  construction; the existing route tests + green `just test` are sufficient proof. **A service extraction**
  (logic moved into a `backend/core` fn) is *adapted* code — it MUST add a direct unit test for the new pure
  fn (no `TestClient`; assert input→output). Say which in the row.
- **The justification column is mandatory.** One sentence: *which* metric moved and why this wasn't a shovel.
  Empty justification = reverted row.

## Coupling probe (run before every extraction — this is the gate's instrument)

Paste the region's line range; get its back-import surface against the god-file's private helpers:

```bash
cd /home/joshua/NADOC
FILE=backend/api/crud.py        # or backend/api/assembly.py
START=13144; END=13383          # the candidate region's banner-to-banner range
mapfile -t HELPERS < <(grep -nE '^(def|async def) _' "$FILE" | sed -E 's/.*(def|async def) (_[a-zA-Z0-9_]+).*/\2/' | sort -u)
body=$(sed -n "${START},${END}p" "$FILE")
for h in "${HELPERS[@]}"; do
  c=$(echo "$body" | grep -cE "\b${h}\b")
  defin=$(echo "$body" | grep -cE "^(def|async def) ${h}\b")   # defined inside range? then internal
  [ "$c" -gt 0 ] && [ "$defin" -eq 0 ] && echo "  ${h}(${c})"
done
```

`B` = number of lines this prints. Each printed `_helper(n)` is a symbol you'll either import back (counts
toward B) or co-extract. The `(n)` is how many call sites — high `n` on a kernel helper (`_design_response`)
is fine; high `n` on a bespoke helper means real entanglement.

## Lessons learned (append as the loop teaches them — the durable payoff)

_Seeded at bootstrap from the carve-up design + the two existing exemplars. Add a numbered lesson whenever a
session discovers something a future session would otherwise re-learn the hard way._

> **DIGEST (read this; drop into the full L-N entry only for the detail).** The 22 lessons below cluster into
> six durable rules:
> 1. **Measure B, not LOC** (L1, L2) — back-import surface is the win; the shared kernel (`_design_response`/
>    `_assembly_response`, mutate wrappers, many-caller lookups, L4-blocked file-IO) counts toward B but never
>    blocks. Ship at **bespoke-B=0** even when raw B is 4–11 (L19).
> 2. **Cut on cohesion + dependency-direction, not the banner** (L8, L12, L14) — a `# ──` banner groups by
>    adjacency; read the whole span and move only the routes/helpers sharing one reason to change.
> 3. **Classify each helper by its BODY, not its banner or an inherited label** (L13, L15, L17, L20) — grep the
>    body for api symbols / file-IO / `HTTPException`: pure→push to `backend/core` (+unit test), api-bound→leave
>    and import back, mixed→split (pure core fn + thin api shim). Don't re-trust a prior "L4-blocked" tag.
> 4. **Reachability (and deletion-safety) is a whole-repo property** (L10, L16, L21, L22) — before
>    moving/deleting/re-exporting ANY symbol, `grep -rn` across `backend/` AND `tests/`; a "frontend-dead" route
>    can still have backend route tests (delete them in the same commit); mutable module globals must be read
>    through their module.
> 5. **Verbatim lift = behavior preserved by construction; service push = needs a real unit test** (L5, L6) —
>    keep the exact `mutate_and_validate`/`set_*_silent`/`snapshot` usage; verbatim means verbatim.
> 6. **Don't trust a single suite run** (L7, L9, L9-addendum, L18) — stale-server vs real bug; a disjoint-domain
>    failure after a verbatim lift → deterministic isolated before/after to attribute, then chase real root causes
>    (a torn-read/order-flake in shared persistence is a bug, not noise). When routers import kernel helpers BACK,
>    a staying caller's reference to a moved symbol must become a **function-local** import (circular otherwise).
>
> **Discipline (keep this log lean):** a new lesson is **≤4 lines**; if it restates an existing L-N, EXTEND that
> entry (or this digest) instead of adding a near-duplicate. Cite L-numbers in metrics rows; don't renumber.

- **L1 — B, not LOC, is the win.** The whole loop exists because "crud.py got shorter" is a lie if the new
  router imports 25 helpers back. Always probe before, log before→after B, and write the justification line.
- **L2 — The shared kernel helpers are SUPPOSED to be imported back.** `_design_response` &c. live in crud.py
  and are imported by `routes_loop_skip.py` / `routes_camera_poses.py` on purpose (100+ callers; moving them
  would be the bigger coupling). Don't "fix" this by duplicating them. Count them toward B, then ignore them.
- **L3 — URLs never change.** The router carries the same paths; mounting in `main.py` with `prefix="/api"`
  reproduces them. If a frontend `client.js` call breaks, you changed a path — you didn't.
- **L4 — `backend/core` must not import `backend/api`.** The dependency arrow is api→core. A service
  extraction that needs a request model or `state.py` is a sign the logic isn't actually pure yet — pass the
  data in as plain args, keep `state.mutate_and_validate` on the api side.
- **L5 — Verbatim router lift = behavior preserved by construction; service push = needs a real unit test.**
  Don't write a `TestClient` test to "prove" a verbatim move (the green suite already does). DO write a direct
  input→output unit test for any logic you pull into core — that's the adapted code whose pin must be earned.
- **L6 — Respect the mutation contract.** Every handler you move keeps its exact `state.mutate_and_validate` /
  `set_design_silent` / `snapshot` usage (api-and-state.md). Moving a handler must not change which one it
  calls — that silently breaks undo/redo. Verbatim means verbatim.
- **L7 — Stale-server trap.** After moving routes, if a `curl` looks wrong but `just test` is green, it's the
  `--reload` server holding stale in-memory `design_state` — ask the user to restart, don't debug Python
  (api-and-state.md). Tests are the source of truth, not a live curl.
- **L8 — A `# ──` banner groups by adjacency, NOT cohesion (now bitten twice).** #1's "Animations" banner held
  a binding model used elsewhere; #2's "Strand extensions" banner held 4 plate-layout / representation-override
  routes interleaved *between* the extension handlers. Always READ the whole banner-to-banner span and cut on
  the *concept* the new router owns — move only the routes/models that share its one reason to change, leave
  the rest under a retitled banner. The route count you commit to (#2: 5, not 9) is the cohesion check.
- **L9 — Baseline a flake before you trust the count.** The framework's "1753 green" baseline was optimistic:
  `test_seamless_router.py::test_teeth_closing_zig` *appeared* to be a cross-test leak (failed in full suite,
  passed in isolation). When `just test` shows ONE failure after a verbatim router lift, **stash-and-rerun on
  clean HEAD** before assuming you caused it; a verbatim move of routes unrelated to the failing test's domain
  almost never is the cause. **UPDATE (2026-06-08, ISSUE-6):** the "leak" was a misdiagnosis — it was
  hash-seed nondeterminism in the shared `_hamiltonian_path` (no lexicographic tiebreaker), now FIXED; the test
  was re-pinned to the closing-zig topological event. True full-suite green is now **1753 / 0**. The lesson
  still stands (stash-and-rerun to attribute a failure), but the order-dependence was hash-order, not state
  residue — a single-test fresh-process re-run varying pass/fail is the tell for hash nondeterminism, not a leak.

- **L10 — Region-internal helpers can be imported CROSS-FILE; grep the whole `backend/`, not just the god-file.**
  #3's `_parse_params` / `_resolve_cluster_scope` lived under the deformation banner in crud.py but were imported
  by `routes_loop_skip.py`'s `/design/deformation/validate` route. The in-file grep ("used elsewhere in crud.py?")
  found the edit-feature caller but MISSED the cross-file one; the full suite caught it as an `ImportError` after
  the helpers were deleted. **Rule:** before moving/deleting ANY helper, `grep -rn "\b_helper\b" backend/api/`
  (whole dir). If 2+ callers across files, that's the signal to do a **service push to `backend/core` first** —
  which is precisely what turned #3 from a B=3 umbilical-cord lift into a B=1 clean one (all 3 callers now import
  the pure fn from core; none import each other). A shared-across-files api helper is core logic wearing an api hat.

- **L11 — assembly.py is NOT prefix-clean like crud.py; the back-import surface is bimodal.** crud.py's clusters
  almost all sit at B=1 (`_design_response`). assembly.py splits sharply: the *display/metadata* clusters
  (Animation CRUD, Assembly camera poses) are clean B=1 on `_assembly_response` (the assembly-side twin of
  `_design_response` — same shared-kernel status, counts toward B, never blocks), but the *kinematics* clusters
  (Gear relations, Belt paths, PartGroup routes) are all **B=4–5**, entangled with a shared revolute-drive helper
  web (`_apply_assembly_mutation_with_feature_log`, `_resolve_gear_endpoint`, `_gear_endpoint_side`,
  `_build_inst_by_id`, `_propagate_gear_relations_from`, `_sync_revolute_values_*`). **Rule:** drain the B=1
  display clusters first; tackle the kinematics clusters only after a `backend/core` service push of that shared
  helper web (it's FK/gear math wearing an api hat — exactly the L10 pattern). Always probe B on the LIVE range —
  assembly.py's adjacency-grouped banners hide this entanglement.

- **L12 — Folding two adjacent clusters into ONE router is valid (the inverse of L8) when BOTH conditions hold:
  each probes B=1 *independently* AND they share one reason to change.** #5 folded `# ── Assembly configurations`
  (4 routes) + `# ── Assembly camera poses` (4 routes) into `routes_assembly_configs.py` — both are *saved
  assembly view/state presets* persisting list fields on `Assembly` and returning `_assembly_response`, so a
  change to the preset-persistence pattern or the response shape touches both. L8 says a banner can hide
  *non*-cohesive routes (split them out); L12 is the dual — two *separate* banners can be cohesive enough to
  share a module. The test is the same in both directions: **cut on the one-reason-to-change, not the banner.**
  Probe each candidate's B separately before folding (don't assume the second is clean because the first is).

- **L13 — When a region's compute helper depends on an api-layer helper AND is shared cross-region, leave it
  behind and import it back — don't move it (the L4 corollary, the inverse of L10).** #6's
  `_linker_geometry_for_assembly` looked like a service-push candidate (pure-ish, takes the assembly
  explicitly) — but it imports `crud._geometry_for_design` (api layer), so pushing it to `backend/core` would
  invert the api→core arrow (L4). It was also called from the overhang-connections region (~3022/3057) + the
  relax test suite, i.e. **cross-region** (the L10 signal). L10 says "2+ cross-file callers → service push to
  core first" — but that move is only available when the helper is *core-pure*. When it has an api dependency,
  the service push is blocked, so the right call flips: **keep the helper in the god-file as shared
  infrastructure and import it back into the new router** (counts toward B). Moving it would have forced 3+
  *reverse* imports (assembly.py ← routes_assembly_linkers.py) — strictly worse coupling than the one
  back-import. The tell: if a candidate-for-core helper `grep`s an `import` from `backend.api`, it is NOT
  core-ready; probe its callers and decide leave-and-import-back vs. (bigger job) push its api dep to core too.

- **L14 — A fat banner can yield a CLEAN service push of its PURE sub-kernel even when the rest is L4-blocked;
  don't reject the whole region because half of it is entangled.** #7's `# ── Forward kinematics helpers`
  banner (~660 ln, 20 helpers) was earmarked as one big service extraction. But probing the bodies split it
  cleanly in two: (a) a **pure graph-propagation kernel** (5 helpers) whose only deps are numpy + `Mat4x4`
  (core) — zero api dependency, B=0, directly testable; and (b) the connector-resolution + cluster-inference
  helpers, which transitively pull `_design_with_instance_overrides` (→ `_load_design_from_source`: file IO +
  `HTTPException`) and `_mat4_from_model`, i.e. L4-blocked from core. **The right move is to push (a) and leave
  (b)** — a B=0 service extraction with real unit tests beats forcing the whole banner and either inverting the
  api→core arrow or shipping an untestable blob. The tell for the pure sub-kernel: grep each helper's body for
  api-layer symbols / file-IO / `HTTPException`; the ones that touch only numpy + core models are the core-ready
  set. (Method twin of L8/L12: cut on cohesion+dependency-direction, not the banner span.) Verbatim lift keeps
  the helper names underscore-prefixed in core so the ~50 call sites import them back unchanged — a clean public
  rename is an optional later cosmetic, not required when the bodies are byte-identical.

- **L15 — A single helper can split INTO core-pure + api-state halves (the within-function twin of L14).** L14
  split a *banner* across helpers (some core-ready, some L4-blocked). #10's `_patch_references` was ONE function
  that did both: pure on-disk .nass remapping (filesystem + json + the `_remap` closure — core-ready) AND an
  in-memory `assembly_state.get_assembly`/`set_assembly_silent` mutation (L4-blocked). The move is to push the
  pure body to `backend/core` (`patch_nass_files` + `patch_assembly_instances` returning a new model-or-None)
  and leave a **thin api wrapper** that calls the core fns then does the `assembly_state` commit. The wrapper
  keeps the helper's original name + signature so all call sites are unchanged (verbatim from the caller's view)
  while the testable logic relocates. Same for `_safe_workspace_path`: the resolution is pure (→ core, raising
  `ValueError`), the HTTP translation (`ValueError`→`HTTPException(400)`) is the api wrapper's one job. The tell:
  a helper whose body is *mostly* pure but has one `state`/`HTTPException` line — don't reject it as L4-blocked;
  push the pure part and keep the thin api shim. This is what turns a B=4 router into a B≤1 lift-able one.

- **L16 — A module-global a route reads at call-time must be read THROUGH the source module after a lift, or you silently break a `monkeypatch.setattr`.** #11's workspace routes read the module global `_WORKSPACE_DIR` directly; `test_part_edit_doc_isolation.py` does `monkeypatch.setattr(asm_module, "_WORKSPACE_DIR", tmp_path)` to redirect file writes. A naïve `from backend.api.assembly import _WORKSPACE_DIR` in the new router binds the *object* at import time, so a later `setattr` on the assembly module rebinds assembly's name but NOT the router's copy — the route would write to the real workspace while the test thinks it's sandboxed. The full suite stayed green only because that particular test hits the Instance-save route (which stays in assembly.py), not a workspace route — i.e. the breakage would have been **latent**, surfacing only when someone later monkeypatched the dir AND hit a moved route. **Rule:** for a *mutable* module global (constants reassigned by tests/config), import the source module (`from backend.api import assembly as _asm`) and reference `_asm._WORKSPACE_DIR` at call-time, preserving the original read-the-live-global semantics. Function objects (`_safe_workspace_path`) are safe to import directly — they read the global from *their* home namespace at *their* call time, so the patch still reaches them. The tell: grep the region's bare module-global reads (not `def`s) and check whether any test does `monkeypatch.setattr(<that_module>, "<name>", ...)`.

- **L17 — Lifting a self-referential helper cluster shrinks the god-file's surface MORE than the moved LOC
  implies; trim the import-back to what's actually still called.** #12 moved 10 connector-frame helpers to
  `backend/core/assembly_connectors.py`. Five of them (`_build_frame_from_normal`, the three `_resolve_*_local`
  label resolvers, `_local_frame_for_label`) were only ever called by their *siblings* inside the moved set —
  once the whole cluster relocated, those five became fully module-private in core and dropped off assembly.py's
  symbol surface ENTIRELY (no import-back). Only the 5 public-facing resolvers (`_get_connector_world`,
  `_get_connector_world_frame`, `_build_connector_frames`, `_build_world_connector_frames`,
  `_refresh_connector_frames_for_instance`) are imported back. **Rule:** after a multi-helper lift, don't
  reflexively import every moved name back — let ruff F401 tell you which are still referenced in the god-file
  and import only those (the rest are now correctly encapsulated; importing them back would re-expose internals
  and trip F401). The decoupling is better than the LOC-Δ suggests: 10 helpers left, only 5 names re-crossed the
  boundary.

- **L18 — A "kinematics is too entangled, B=4–5" router is actually a CLEAN B=0 SERVICE push in disguise; do the
  push first and the routers fall out (the L11 payoff, realized).** L11 flagged the Gear/Belt/PartGroup/Joint
  routers as B=4–5, entangled with a shared revolute-drive helper web, and said "service-push the web first."
  #15 did exactly that: the whole web (`_propagate_gear_relations_from`, `_sync_revolute_values_*`,
  `_apply_revolute_value_to_gear_endpoint`, `_apply_revolute_joint`, …) turned out to be **pure transform math
  with ZERO api dependency** once two converter calls were swapped to the `Mat4x4` methods that already existed
  (`_mat4_from_model`→`.to_array()`, `_mat4_to_model`→`Mat4x4.from_array()`, both byte-identical — the same trick
  as #12/#13). It reuses the earlier core extractions (`assembly_fk`, `assembly_connectors`), so the dependency
  closure was already in core — only this last layer was marooned. The B=4–5 the routers showed was never *route*
  coupling; it was the routers reaching into shared *helpers*, and helpers belong in core. **Rule:** when a
  cluster of routers all probe high-B against the SAME set of private helpers, that shared set is the real
  extraction target — push it to core (it's almost always pure math wearing an api hat), and the routers drop to
  B≤2 kernel-only. Probe the *helpers'* bodies for api symbols, not just the routers' B. The tell that the push
  is clean: every helper in the web only touches numpy/scipy + core models + already-extracted core modules.

- **L19 — B>3 ships when the *bespoke* back-import count is 0 (the kernel-exemption ceiling).** The B≤3 gate is
  a heuristic for "no umbilical cord of private helpers"; its real target is *bespoke* coupling, not the
  shared-kernel set the contract explicitly exempts ("count toward B but never block"). #17 (Belt paths) shipped
  at B=4 because all four back-imports are that exempt set: `_assembly_response` (kernel) +
  `_apply_assembly_mutation_with_feature_log` (mutate-contract wrapper) + `_find_instance` (54-caller shared
  lookup) + `_resolve_gear_endpoint` (L13 forced shared cross-region, L4-blocked from core). The only bespoke
  helpers in the region (`_find_belt_path`/`_resolve_belt_pulley`) moved IN. So bespoke-B was 0 — the cluster is
  genuinely clean, the 4 is just the shared-kernel headcount. **Rule:** when a probe shows B=4–5, classify each
  symbol before reverting: kernel-response twin, mutate wrapper, a many-caller (>20) trivial lookup, and an
  L13/L4-blocked shared-cross-region helper are all the exempt set. If EVERY back-import is exempt and zero
  bespoke region helpers are pulled back (they moved in), ship it and state bespoke-B=0 in the row. If even one
  back-import is a bespoke region helper, the gate stands — co-extract or pick cleaner. (#14 was the B=3 version
  of this same call; #17 is the B=4 version — same logic, the line is bespoke-B, not raw B.)

- **L20 — Don't trust a prior handoff's "L4-blocked" label on a helper; read its BODY.** #19 inherited a
  handoff that grouped `_cluster_se3` with the L4-blocked cluster-inference trio
  (`_infer_cluster_ids_for_connector_label` &c., which genuinely call `_design_with_instance_overrides` → file-IO).
  But `_cluster_se3`'s body touches only numpy/scipy + model fields (`ct.rotation`/`pivot`/`translation`) — it is
  **pure**, with a single in-region caller, so it moved IN with the routes cleanly (no back-import, no core push
  needed). An L4 classification is a property of the *body*, not of the banner/region a helper sits in or what a
  prior session asserted — a one-look `sed -n` at the def settles it. The tell that a "blocked" helper is actually
  free: grep its body for `_design_with_instance_overrides` / `_load_design_from_source` / `open(` / `HTTPException`
  — none present ⇒ it's core-pure (push to `backend/core`) or router-local (move IN), not blocked. (Twin of L14's
  "grep each helper's body for api symbols," applied to *re-litigating an inherited classification.*)

- **L21 — F401 "unused" on a re-exported core symbol does NOT mean unused; grep `tests/` too before deleting it.**
  #20 moved the joint routes out of assembly.py, which made assembly.py's `from backend.core.assembly_connectors
  import _get_connector_world` re-export locally unused — ruff F401 flagged it, I removed it, and `just test`
  went RED with an `ImportError` because `tests/test_periodic_polymer.py` did `from backend.api.assembly import
  _get_connector_world`. assembly.py was acting as a **re-export shim**: a core helper imported there for the
  routes was *also* being reached by a test through the api module's namespace. L17 says "let F401 tell you which
  to import back" — true for back-imports of the god-file's OWN helpers, but a `from backend.core...import _x`
  line in the god-file is ALSO a public re-export other modules/tests may depend on. **Rule:** before deleting an
  F401-flagged `from backend.core... import _helper` line, `grep -rn "import _helper" tests/ backend/` (whole
  repo, not just `backend/api/`). If anything imports it *via the god-file*, either (a) fix that importer to point
  at the true core home (the correct decoupling — what #20 did: the test now imports from
  `backend.core.assembly_connectors`), or (b) keep the re-export with `# noqa: F401`. The tell: a deleted import
  that ruff calls "unused" but that names a symbol other files reference — the god-file was its public doorway.
  (Twin of L10/L16: a symbol's reachability is a whole-`backend/`-plus-`tests/` property, not a single-file one.)

- **L9-addendum (2026-06-15, #24) — a "flaky" failure in a DISJOINT domain after a verbatim lift is a clue, not
  noise; chase it to root cause.** #24's `just test` flagged `test_oxdna_relaxation.py::test_runner_end_to_end`
  (`JSONDecodeError`). It was NOT extraction-caused — but it was also NOT "just flaky": the root cause was a real
  torn-read race in `OxdnaJob.save` (non-atomic `write_text` truncates job.json while the status-poll endpoint /
  `_wait_terminal` read it concurrently → empty read → `JSONDecodeError`). **FIXED** (atomic temp-file +
  `os.replace`), reproduced pre-fix (failed by loop iter 7, `s=''`) and stress-validated post-fix. **Rule:** when
  a disjoint-domain test fails after your verbatim lift, (1) confirm it's not yours with a deterministic isolated
  before/after (`-p no:randomly`, your files only) — but (2) don't stop at "flaky"; a torn-read / order-flake in
  shared persistence is a real bug worth fixing so it stops poisoning the gate. See the difficulties ledger entry
  (now RESOLVED).

- **L22 (2026-06-15) — "dead route" means dead in `frontend/src` AND `tests/`; grep BOTH before deleting, and
  delete the route's tests in the SAME edit.** The post-#26 Part-library deletion (3 routes confirmed
  frontend-dead by `rg "assembly/library" frontend/src` = empty) went **5-RED** on the full deterministic suite
