# Isolated oxDNA physics A/B audit — 2026-09-13

These are experimental validation tools, **not production patches or an engine installer**. The audit preserves the managed engine and its source, tests one factor at a time, and keeps both possible protein–DNA excluded-volume amplitudes. See [the report](../../../docs/validation/oxdna_physics_ab_2026-09-13.md) and its machine-readable JSON.

## Scope and provenance

The baseline is NADOC's `8028cf33b3cba12992b771156085fa54879f50cd-adaptive-memory-bussi-v2`. `baseline_source.patch` records its differences from the pinned upstream source. `candidate_patches/` contains changes relative to that baseline, plus local build hashes. CPU and CUDA interaction code initially disagree on the protein–DNA amplitude; neither amplitude is designated experimentally correct by this audit.

`fixtures.tar.gz` contains the exact fixed-gold starting configurations and upstream example inputs used here. `fixture_hashes.json` records every fixture hash. The cage and KDPG inputs originate in the pinned oxDNA repository; upstream's GPL license accompanies this package. The fixed-gold fixtures were generated by NADOC from the streptavidin model described in the linked reports. These inputs do not constitute an experimental validation dataset.

The local CUDA builds use mixed precision, CUDA 12, architecture 75, and the same release/compiler options for every variant. Local builds use two compiler jobs because this WSL instance previously crashed. Alpine uses GCC 14.2, portable CPU builds, four compilation workers, and one core per simulation. Its array is limited to 18 simultaneous jobs.

## Reproduce

Run from the repository root using the project virtual environment. Existing outputs are not automatically safe to overwrite: use a separate checkout for a new campaign. The staging command verifies the managed source revision and baseline patch and refuses to overwrite differing audit files.

```bash
.venv/bin/python scripts/validation/oxdna_physics_ab/prepare_local.py --build
```

This stages the scripts and fixtures under `workspace/validation/physics_ab_20260913` and builds isolated engines there. It never changes the managed `current` symlink. Run the following **sequentially**, retaining failures:

```bash
.venv/bin/python workspace/validation/physics_ab_20260913/functional_ab.py
.venv/bin/python workspace/validation/physics_ab_20260913/extended_ab.py
.venv/bin/python workspace/validation/physics_ab_20260913/dna_probe.py
.venv/bin/python workspace/validation/physics_ab_20260913/workflow_ab.py
.venv/bin/python workspace/validation/physics_ab_20260913/sensitivity_ab.py
.venv/bin/python workspace/validation/physics_ab_20260913/prepare_campaign.py
```

`extended_ab.py` includes the intentionally retained failure of the raw ideal DNA fixture on CUDA. `dna_probe.py` tests normalized, raw, and CPU-prepared coordinates with both GPU interaction paths. `workflow_ab.py` uses the CPU-prepared configuration for ordinary-DNA force and timestep controls. Its Brownian-renderer A arm is expected to fail for a missing diffusion parameter; the candidate renderer is an isolated copy, never imported by the application.

For each index 0–53, run the native GPU case:

```bash
.venv/bin/python workspace/validation/physics_ab_20260913/campaign_worker.py --backend CUDA --index 0
```

The CPU worker accepts `--backend CPU`. The supplied Alpine scripts reference this user's existing authorized project directory and toolchain; adapt those paths for another system. Stage `cpu_inputs.tar.gz`, build with `alpine_native_build.sbatch`, require its preflight to pass, and then submit `alpine_runs.sbatch`. **Do not substitute LD_PRELOAD:** the existing Alpine CPU executable is statically linked. The failed interposition preflight and two canceled exploratory jobs were excluded from the accepted campaign.

Only derived `status_CPU/*.json` files need downloading; full trajectories can remain on Alpine. Then run:

```bash
.venv/bin/python workspace/validation/physics_ab_20260913/summarize_ab.py
```

The summary writes the report JSON under `docs/validation/`. It reports incomplete cases explicitly. Empty exception messages count as failures; process exit zero does not establish finite output.

## Acceptance and limits

- Pair force/torque error must be below `1e-3` against the independently evaluated potential with the specified amplitude. Outside-cutoff and protein–protein controls must remain unchanged.
- The weak-coupling Bussi test allows less than 0.1% kinetic-energy change at `tau=1e9`.
- Point rotations must be zero. Compare physical positions, velocities, and DNA orientations; protein point orientations have no physical meaning in the non-angular DNANM model.
- CUDA atomics can perturb interacting trajectories. Use repeated unchanged binaries as controls; long trajectory identity is not a CPU/GPU ensemble criterion.
- Runtime comparisons are paired within the same hardware/backend, with randomized A/B order and identical output cadence. Report uncertainty and reject reproducible slowdowns. A 5% measurement-resolution target is **not permission for a 5% slowdown**.
- The full campaign has three independent seeds, three geometries, six arms, and two backends: 108 runs of 100,000 steps at `dt=0.0001`. It is a screening experiment, not proof of equilibration or experimental accuracy. Report wide intervals and poor mixing as inconclusive, not equivalent.
- Temperature means use independent replicas for inference. The final Holm family contains 108 subsystem/arm/geometry/backend tests. Autocorrelation-based effective sample sizes are diagnostics only when drift may remain.
- No amplitude, thermostat, diffusion coefficient, spring constant, or production default is automatically selected from these results.

## Follow-ups retained in this audit

`additional_ab.py` tests the ordinary-DNA2 average-parameter mismatch exposed by the regression matrix, using upstream's explicit average parameter file without altering a kernel. It also repeats the cage runtime comparison with frequent output. `energy_precision.py` re-evaluates saved NVE frames with the installed DNAnalysis executable at 15-digit precision; it does not run dynamics. `analyze_sensitivity.py` extracts protein-network strain and tip covariances from saved sensitivity trajectories.

`prepare_long.py` stages a separate nine-case-per-backend follow-up under `long_campaign/`: the biotin-linked geometry, three seeds, baseline/current-K/Brownian amplitude-1 arms, one million steps. Build reuse is explicit through links to the frozen engines; the short screen is retained. Run its worker for indices 0–8 and submit its own Alpine script (75-minute per-task limit) after staging. `summarize_ab.py` includes both campaigns, and `write_report.py` renders the Markdown report. A partially completed campaign is labeled incomplete.

The accepted CPU short array was 32541315; the long array was 32541783. Initial failed wrapper/interposition attempts were not accepted as physics validation. Local CPU and GPU benchmark jobs ran sequentially; light postprocessing of saved frames was allowed while the later GPU sampling campaign ran. No performance benchmark overlapped another local simulation or build.

`prepare_full_nve.py` stages 18 complete-build NVE cases per backend under `full_nve/`: three geometries, both matched contact amplitudes, and three timesteps over equal duration. Run `full_nve/worker.py` for indices 0–17 per backend. Stage its input archive into the remote `full_nve` directory, with links to the frozen fixtures and engines, before submitting its Alpine script. The accepted CPU array was 32542632. Download its `status_CPU` directory separately from the other campaigns.

The NVE energy includes native internal potential plus kinetic energy at 15-digit precision and independently reconstructed gold, anchor, and linker potentials. Reciprocal linker force blocks count once. Conservation requires peak-to-peak energy below 0.001 DOF kBT; the separate quadratic-scaling criterion requires both successive log2 standard-deviation ratios in [1.5, 2.5]. A bounded but nonquadratic result does not pass both criteria.

After completing all campaigns and postprocessing, run `summarize_ab.py`, `plot_report.py`, and `write_report.py` in that order. The final artifact requires 108 short, 18 long, and 36 full-build NVE cases. The newly discovered CUDA zero-vector normalization guard was not built in this campaign; its regression and runtime validation remains outstanding. No candidate is automatically promoted.
