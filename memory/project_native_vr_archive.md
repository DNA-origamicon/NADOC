# Native VR expansion archive

Historical detail moved from `project_native_vr.md` at the scene-v12 phase boundary. Git history remains the byte-exact record; this file retains the decisions needed to interpret the active plan.

## Phases 0–4 summary

- Phase 0 inventoried desktop authorities for same-helix gaps, crossovers and forced ligations, crossover extra bases, extensions, overhangs/linkers, ends, flexible details, and warnings. Each visual fact requires stable topology/geometry parity plus a headset-rendered check.
- Phase 1 projected authoritative domain segments, explicit cross-helix chords, ordered crossover-insert beads/slabs/connectors, extension chemistry markers, overhang half/full cylinders, ss/ds linker paths and bridges, flexible runs, and unligated warning signs. Automated gates passed; the consolidated headset visual gate remains open.
- Phase 2 introduced stable scene-v6 identities and numeric comparison by semantic owner, with explicit position/orientation/dimension/color tolerances and duplicate rejection.
- Phase 3 introduced natural/Expanded paired scene-v7 poses and hold-to-expand on the original Vive right grip. Geometry sizes stay constant while helix spacing changes; the comfort/controller-conflict headset gate remains open.
- Phase 4 added exact native picking, private sequenced hover/select intents, desktop-mirrored hover, canonical selection levels, browser acknowledgement, stable green selection feedback, owner aliases, cross-representation fallback, exact half-cylinder picking, and ordinary/atomistic bond ownership. The native viewer never became a second selection writer.

## Archived validation principles

- Negative space is a geometry fact: an intentional domain gap must remain empty.
- Curves and interpolated detail use ordered source parameters, not display-segment indices as chemical identity.
- Canonical selection acknowledgement is exact-to-coarse and browser-authoritative.
- Representation fallback may use explicit owner aliases only; delimiter parsing and fuzzy identity matching are prohibited.
- Hover is renderer-only; Select uses the canonical selection controller; tools use action-time target snapshots.
- Manual headset evidence is still required for Phases 1, 3, and 4 despite automated numeric parity.
